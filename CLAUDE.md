# CombatTracking

WoW 3.3.5a (build 12340, Interface 30300) addon that shows the combat state of target, focus, party and arena units,
with a swipe/timer for when each unit can leave combat. Used mainly in arena. Lua 5.1, Ace3 libraries embedded in
`libs/`. User-facing behaviour is described in `README.md`.

## Files
- `Core.lua` - the combat model, with no frames. `Core.NewTracker(env)` takes the unit API it needs
  (`UnitIsEnemy`, `UnitCanAttack`, `UnitAffectingCombat`) so it runs outside the game. The header comment lists
  the server rules it follows; keep it in sync when the model changes.
- `CombatTracking.lua` - icons, events (`COMBAT_LOG_EVENT_UNFILTERED`, `UNIT_FLAGS`, ...), sounds, Gladius
  attachment, AceDB profile and legacy migration, slash commands. Feeds events into `CT.tracker`.
- `Options.lua` - AceConfig options table (`/ct`).
- `SpellData.lua` - generated by `tools/gen_spelldata.py` from Spell.dbc. Never edit by hand; see README
  "Spell data". The DBC files are in `D:\TrinityCoreServer\Build\bin\RelWithDebInfo\dbc`.
- `screenshots/` - README images, taken in game by `Showcase.lua` of the test addon (suite `CT_Showcase`; its
  header lists the client settings). Not part of releases.
- `sounds/` - sounds registered with LibSharedMedia (paths in `CombatTracking.lua`).
- `tools/make_release.py` - builds `dist/CombatTracking-<version>.zip` from the working directory, or from a
  commit given as argument (version from the `.toc`). `tools/make_release_head.py` calls it with HEAD.

Load order is in `CombatTracking.toc`: `embeds.xml` (libs), `SpellData.lua`, `Core.lua`, `CombatTracking.lua`,
`Options.lua`. Everything hangs off the global `CombatTracking` (`CT`); `CT.Core` is the model.

## Combat model
The model mirrors TrinityCore (`src/server/game/Combat/CombatManager.cpp`, `Spells/`) and the client
decompilation; check those sources instead of guessing (see the global CLAUDE.md for paths). Facts verified in
game, which need no new research:
- PvP combat ends 5.0 s after the last hostile contact of a pair.
- Spells with a cast time log only `SPELL_CAST_START`; `SPELL_CAST_SUCCESS` is logged only for instant spells.
- Mass Dispel on a unit without buffs refreshes combat but logs nothing; overdue timers are explained by finished
  Mass Dispels (`UNIT_SPELLCAST_SUCCEEDED`).
- Mind Control ends the priest-victim combat at once on TrinityCore. The addon still keeps them in combat; the
  user has not decided which server's behaviour to follow, so leave that rule unless asked.

## Tests
Tests live in the Trinity client, not in this repo:
`D:\Games\World of Warcraft 3.3.5a - Trinity\Interface\AddOns\Unit_Tests_CombatTracking` (the client's
`CombatTracking` folder is a junction to this repo).
- Offline tests of `Core.lua` and `SpellData.lua` (no game needed, run these after every model change):
  ```
  "C:/Program Files (x86)/Lua/5.1/lua.exe" Offline/unit_tests.lua
  ```
  run from the test addon folder. `Offline/benchmark.lua` measures combat log throughput.
- In-game tests (`Unit_Tests_CombatTracking.lua`): load the `wow-ui-tests` skill first and ask before launching
  the client.

## Conventions
- Tabs for indentation in Lua; comments are short, plain sentences explaining the why (often the server rule).
- Only the WoW 3.3.5a API exists (no C_ namespaces, no `C_Timer`); check `D:\Repositories\wowdecomp` for API
  details.
- Update the README "How it works" / "Limitations" sections when behaviour changes.
- Commit messages: one short imperative sentence, no prefix (e.g. "Refresh the caster's timer when Mass Dispel
  finishes").
- Releases: bump `## Version` in the `.toc`, commit, then run `python tools/make_release_head.py`.
